# LangGraph 记忆持久化方案 - 开发笔记

## 背景

### 问题

原来的 `AIOpsService` 使用 `MemorySaver()` 作为 LangGraph 的检查点存储。`MemorySaver()` 将所有会话状态保存在**进程内存**中：

```python
self.checkpointer = MemorySaver()  # ❌ 纯内存存储，重启即丢失
```

这意味着：
- 应用重启后，所有历史会话状态全部清空
- 多实例部署时，各实例之间无法共享会话数据
- 无法进行会话管理和数据备份

### 解决方案

设计一套**可切换、生产级别**的记忆持久化方案：

1. 定义**抽象存储接口** - 与具体实现解耦
2. 实现**SQLite 引擎** - 开发/单机场景（零依赖）
3. 实现**PostgreSQL 引擎** - 生产场景（支持多实例）
4. 通过**工厂模式** - 环境变量一键切换

## 逐层详解

### 1. 抽象接口层

**文件:** `app/core/storage_engine.py`

定义了所有存储引擎必须实现的方法，类似于"合同"：

```python
class AbstractStorageEngine(ABC):
    @abstractmethod
    async def save_state(self, thread_id: str, state: dict) -> None
        """保存会话状态"""

    @abstractmethod
    async def get_state(self, thread_id: str) -> dict | None
        """获取会话状态"""

    @abstractmethod
    async def list_sessions(self) -> list[str]
        """列出所有会话ID"""

    @abstractmethod
    async def delete_state(self, thread_id: str) -> bool
        """删除会话状态"""

    @abstractmethod
    async def check_health(self) -> bool
        """健康检查"""
```

**为什么需要抽象接口？**
- 存储引擎可以随时替换（SQLite ↔ PostgreSQL）
- 未来可以方便地扩展（如 Redis、MongoDB）
- 业务代码不依赖具体实现

### 2. SQLite 引擎（开发/单机）

**文件:** `app/core/storage_sqlite.py`

使用 `aiosqlite`（异步 SQLite）实现：

```python
class SQLiteStorageEngine(AbstractStorageEngine):
    def __init__(self, db_path: str):
        self.db_path = db_path  # 数据库文件路径
        self._initialized = False
```

**表结构：**
```sql
CREATE TABLE sessions (
    thread_id TEXT PRIMARY KEY,          -- 会话ID
    state_json TEXT NOT NULL,            -- 状态数据（JSON 序列化）
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,  -- 最近更新
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP    -- 创建时间
);
```

**关键实现细节：**

- **惰性初始化** - 第一次使用时才创建表，避免启动时不必要的文件操作
- **UPSERT** - 使用 `ON CONFLICT DO UPDATE` 实现"存在即更新，不存在即插入"
- **JSON 序列化** - 将 dict 状态转为 JSON 字符串存储

```python
async def save_state(self, thread_id: str, state: dict) -> None:
    await self._ensure_initialized()
    async with aiosqlite.connect(self.db_path) as db:
        await db.execute("""
            INSERT INTO sessions (thread_id, state_json, updated_at)
            VALUES (?, ?, CURRENT_TIMESTAMP)
            ON CONFLICT(thread_id) DO UPDATE SET
                state_json = excluded.state_json,
                updated_at = CURRENT_TIMESTAMP
        """, (thread_id, json.dumps(state, ensure_ascii=False)))
        await db.commit()
```

### 3. PostgreSQL 引擎（生产）

**文件:** `app/core/storage_postgres.py`

使用 `asyncpg`（高性能异步 PostgreSQL 驱动）：

```python
class PostgreSQLStorageEngine(AbstractStorageEngine):
    def __init__(self, url: str):
        self.url = url          # 数据库连接 URL
        self._pool = None       # 连接池（延迟初始化）
```

**与 SQLite 的关键区别：**

| 特性 | SQLite | PostgreSQL |
|------|--------|------------|
| 连接方式 | 每次创建连接 | 连接池复用 |
| JSON 类型 | TEXT（文本存JSON） | JSONB（原生二进制JSON） |
| 部署要求 | 无（文件型） | 需要 PostgreSQL 服务 |
| 多实例 | ❌ 不支持 | ✅ 支持 |

**连接池模式：**
```python
# 使用连接池管理数据库连接
self._pool = await asyncpg.create_pool(self.url)

# 从连接池获取连接
async with pool.acquire() as conn:
    await conn.execute(...)
```

### 4. 工厂模式（切换引擎）

**文件:** `app/core/storage_factory.py`

通过 `STORAGE_BACKEND` 环境变量决定使用哪个引擎：

```python
def get_storage_engine() -> AbstractStorageEngine:
    """全局单例"""
    global _storage_engine
    if _storage_engine is None:
        backend = config.storage_backend  # 从.env读取

        if backend == "sqlite":
            _storage_engine = SQLiteStorageEngine(config.storage_sqlite_path)
        elif backend == "postgresql":
            _storage_engine = PostgreSQLStorageEngine(config.storage_postgres_url)

    return _storage_engine
```

**切换方式（.env）：**
```bash
# 开发环境
STORAGE_BACKEND=sqlite
STORAGE_SQLITE_PATH=./volumes/langgraph.db

# 生产环境（取消注释即可切换）
# STORAGE_BACKEND=postgresql
# STORAGE_POSTGRES_URL=postgresql://user:pass@host:5432/db
```

### 5. 业务层集成

**文件:** `app/services/aiops_service.py`

#### 5.1 初始化时获取存储引擎

```python
class AIOpsService:
    def __init__(self):
        self.storage = get_storage_engine()  # ✅ 获取持久化存储
        self.checkpointer = MemorySaver()    # LangGraph 仍需 MemorySaver
        self.graph = self._build_graph()
```

**注意：** LangGraph 的 `MemorySaver()` 依然保留（用于图的状态追踪），我们在此基础上**额外添加了持久化层**。

#### 5.2 执行前恢复历史状态

```python
async def execute(self, user_input, session_id):
    # ✅ 从数据库恢复历史状态
    saved_state = await self.storage.get_state(session_id)

    if saved_state:
        # 从数据库恢复历史状态，只更新当前输入
        initial_state = dict(saved_state)
        initial_state["input"] = user_input
    else:
        # 全新会话，初始化状态
        initial_state = {"input": user_input, "plan": [], ...}
```

#### 5.3 每步执行后自动持久化

```python
async for event in self.graph.astream(input=initial_state, ...):
    for node_name, node_output in event.items():
        # ... 处理事件 ...

        # ✅ 每个步骤后自动持久化
        current_state = self.graph.get_state(config_dict)
        if current_state and current_state.values:
            await self.storage.save_state(
                session_id,
                dict(current_state.values)  # 转 dict 后存储
            )
```

#### 5.4 最终状态持久化

```python
# 获取最终状态
final_state = self.graph.get_state(config_dict)

# ✅ 最终状态也要持久化
if final_state and final_state.values:
    await self.storage.save_state(session_id, dict(final_state.values))
```

## 常见问题

### Q: 为什么同时保留 MemorySaver 和持久化引擎？

A: `MemorySaver` 是 LangGraph 的检查点机制（用于图的状态追踪和流程控制），而持久化引擎是我们额外添加的数据层。两者职责不同：
- `MemorySaver` → 运行时状态管理
- `StorageEngine` → 持久化数据存储

### Q: 如何切换到 PostgreSQL？

A: 修改 `.env` 文件，注释 SQLite 配置，取消注释 PostgreSQL 配置，然后确保 PostgreSQL 服务运行即可。

### Q: 存储的数据会不会太大？

A: 每个会话的状态是一个 JSON 对象，通常几 KB ~ 几十 KB。SQLite 可以轻松处理百万级记录，PostgreSQL 更是企业级存储。
