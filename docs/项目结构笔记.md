# SuperBizAgent Python 项目结构笔记

> 面向 Java 开发者的 Python 项目解读

## 一、项目简介

**SuperBizAgent** 是一个企业级智能运维助手（AIOps），结合了 RAG 知识库问答和自动化故障诊断。版本 1.2.1。

**类比 Java 项目：** 如果你熟悉 Spring Boot，这个项目就相当于一个 Spring Boot 应用 —— FastAPI 是 Web 框架，LangChain/LangGraph 是 AI 编排框架（类似 Spring AI），Milvus 是向量数据库（类似 Elasticsearch 但专门存向量）。

### 4.5 `app/services/` — 服务层（Service）

| 文件 | 作用 | 说明 |
|---|---|---|
| `rag_pipeline.py` | RAG 统一管道（深模块） | 对外仅暴露 query()/retrieve()/ingest()，内部组合向量检索、关键词检索、RRF 合并、重排与文档入库 |
| `rag_agent_service.py` | RAG 聊天 Agent | 核心服务，创建 LangGraph Agent，整合知识库检索 + MCP 工具，支持流式/非流式 |
| `aiops_service.py` | AIOps 诊断服务 | Plan-Execute-Replan 模式的 LangGraph 工作流 |
| `router_service.py` | 智能路由服务 | 调用 RouterAgent 决策并分发到 RAG / AIOps / Multi-Agent，统一事件流 |
| `vector_store_manager.py` | 向量存储管理 | 封装 Milvus 向量数据库的增删查操作 |
| `vector_embedding_service.py` | 向量嵌入服务 | 调用 DashScope API 将文本转为 1024 维向量 |

> 注：原 `vector_index_service.py` 与 `vector_search_service.py` 已删除，其职责并入 `RAGPipeline`。

### 4.6 `app/agent/` — AI Agent 核心逻辑

这是项目最核心的部分，实现了 AIOps 自动诊断的 Agent 工作流。

| 文件 | 作用 |
|---|---|
| `mcp_client.py` | MCP 客户端管理，带重试机制（指数退避，最多 3 次） |
| `aiops/state.py` | 定义 Agent 状态（输入、计划、已执行步骤、最终响应） |
| `aiops/planner.py` | **规划器**：查询知识库获取相关经验，生成诊断计划 |
| `aiops/executor.py` | **执行器**：逐步执行计划，调用 MCP 工具获取日志/指标数据 |
| `aiops/replanner.py` | **重规划器**：评估执行结果，决定继续/重新规划/生成报告 |
| `aiops/utils.py` | 工具描述格式化辅助函数 |

**工作流程（类比）：**
```
用户问题 → Planner（制定诊断计划）
         → Executor（执行计划步骤，调用日志/监控工具）
         → Replanner（评估结果，决定下一步）
         → 最终生成诊断报告
```

这就像一个自动化运维工程师：先看知识库找类似案例 → 制定排查步骤 → 逐步执行 → 根据结果调整 → 输出报告。

## 六、数据流

### 6.1 RAG 聊天流程

```
用户提问 → Chat API → RagAgentService
  → Agent 决定调用 retrieve_knowledge 工具
    → 向量搜索 Milvus（找到相关文档）
  → Agent 也可能调用 MCP 工具（查日志/指标）
  → Agent 综合所有信息生成回答
  → 返回给用户（流式 SSE 或一次性）
```

### 6.2 AIOps 诊断流程

```
用户触发 AIOps → AIOps API → AIOpsService
  → Planner: 查知识库 → 生成诊断计划
  → Executor: 逐步执行（调用 MCP 工具查日志/指标）
  → Replanner: 评估结果 → 决定继续/重规划/生成报告
  → 输出结构化诊断报告
```

### 6.3 文档索引流程

```
上传文件 → File API → 保存到 ./uploads/
  → DocumentSplitter: 分块（Markdown 按标题拆 → 按大小拆 → 合并小块）
  → Embedding: 文本 → 1024 维向量（DashScope API）
  → VectorStore: 存入 Milvus collection "biz"
```

## 八、与 Java 项目的关键差异

| 方面 | Java | Python（本项目） |
|---|---|---|
| 类型系统 | 强类型，编译期检查 | 动态类型 + Pydantic 运行时校验 + mypy 静态检查 |

| 包管理 | Maven / Gradle | uv（新一代）/ pip |

| 配置加载 | application.yml + @Value | .env + pydantic-settings |
| 异步编程 | CompletableFuture / WebFlux | async/await（原生支持） |
| 代码风格 | 无统一标准（各团队不同） | Black（格式化）+ Ruff（Lint）强制统一 |

## 九、快速上手命令

```bash
# 1. 安装依赖（类似 mvn install）
uv sync

# 2. 启动 Milvus 数据库（Docker）
docker compose -f vector-database.yml up -d

# 3. 启动 MCP 服务器
python mcp_servers/cls_server.py &
python mcp_servers/monitor_server.py &

# 4. 启动主应用
uvicorn app.main:app --host 0.0.0.0 --port 9900

# 5. 上传知识库文档
curl -X POST http://localhost:9900/api/index_directory \
  -H "Content-Type: application/json" \
  -d '{"directory": "./aiops-docs"}'

# 或者在 Windows 上一键启动：
start-windows.bat
```

| 单例变量 | 所在文件 | 作用 |
|---|---|---|
| `config` | `app/config.py` | 全局配置 |
| `milvus_manager` | `app/core/milvus_client.py` | Milvus 连接管理 |
| `llm_factory` | `app/core/llm_factory.py` | LLM 实例工厂 |
| `vector_store_manager` | `app/services/vector_store_manager.py` | 向量存储 |
| `vector_embedding_service` | `app/services/vector_embedding_service.py` | 嵌入服务 |
| `rag_agent_service` | `app/services/rag_agent_service.py` | RAG Agent |
| `aiops_service` | `app/services/aiops_service.py` | AIOps 诊断 |
| `report_store` | `app/core/diagnosis_report_store.py` | 诊断报告存储 |
