# 应用错误告警处理方案

## 告警名称
- **告警名**: `ApplicationError`
- **告警级别**: 警告/严重
- **触发条件**: 应用错误率超过阈值（如5xx错误率超过1%）

## 问题描述
应用错误会导致：
- 用户请求失败
- 业务功能异常
- 用户体验下降
- 数据不一致
- 收入损失

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确定错误发生时间范围

### 步骤2: 查询应用错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 最近30分钟
- **查询条件**: `level:ERROR OR status:500 OR status:502 OR status:503`

**查询示例**:
```
地域: ap-guangzhou
日志主题: application-logs
时间范围: [当前时间-30分钟] 到 [当前时间]
查询语句: (level:ERROR OR status >= 500) AND service_name:*
```

### 步骤3: 分析错误类型和分布
从日志中提取：
- 错误类型（空指针、超时、异常等）
- 错误发生的接口
- 错误发生的实例
- 错误的堆栈信息

### 步骤4: 查询业务日志
**工具**: `query_logs`
**参数要求**:
- **查询条件**: `business_error OR validation_error`

### 步骤5: 检查最近变更
分析：
- 最近是否有代码发布
- 最近是否有配置变更
- 最近是否有数据库变更
- 最近是否有依赖服务变更

## 常见原因分析

### 原因1: 代码Bug
**特征**:
- 特定接口持续报错
- 日志中有明确的异常堆栈
- 错误类型一致（如NullPointerException）
- 最近有代码发布

**处理方案**:
1. **立即处理**:
   - 查看错误堆栈定位问题
   - 回滚到上一个稳定版本
   - 关闭有问题的功能开关
   - 重启应用实例

2. **问题修复**:
   - 修复代码bug
   - 编写单元测试
   - 进行代码审查
   - 重新发布

3. **预防措施**:
   - 加强代码审查
   - 完善测试覆盖
   - 实现灰度发布
   - 建立回滚机制

### 原因2: 参数校验失败
**特征**:
- 日志中有参数校验错误
- 特定请求参数导致失败
- 前端参数格式错误
- 数据验证失败

**处理方案**:
1. **立即处理**:
   - 加强参数校验
   - 返回友好的错误信息
   - 记录错误的请求参数
   - 通知前端修复

2. **问题修复**:
   - 修复参数校验逻辑
   - 统一参数校验框架
   - 增加参数格式检查
   - 完善错误提示

3. **预防措施**:
   - 统一参数校验
   - API文档完善
   - 接口测试覆盖
   - 参数格式检查

### 原因3: 第三方服务调用失败
**特征**:
- 日志中有第三方服务调用错误
- 超时或连接失败
- 第三方服务返回错误码
- 依赖服务不稳定

**处理方案**:
1. **立即处理**:
   - 启用降级策略
   - 使用缓存数据
   - 异步调用第三方服务
   - 返回默认值

2. **容错优化**:
   - 实现熔断机制
   - 配置重试策略
   - 设置超时时间
   - 实现降级逻辑

3. **监控优化**:
   - 监控第三方服务状态
   - 告警第三方服务异常
   - 记录调用成功率

### 原因4: 数据库操作失败
**特征**:
- 日志中有数据库错误
- 事务回滚
- 数据库连接失败
- 数据校验失败

**处理方案**:
1. **立即处理**:
   - 检查数据库状态
   - 重启数据库连接
   - 检查数据完整性
   - 回滚异常事务

2. **问题排查**:
   - 查看数据库错误日志
   - 检查数据约束
   - 验证数据格式
   - 检查数据库连接

3. **优化改进**:
   - 加强数据校验
   - 优化数据库操作
   - 实现事务管理
   - 添加数据备份

### 原因5: 资源不足
**特征**:
- 内存不足（OOM）
- 线程池耗尽
- 连接池耗尽
- 文件描述符不足

**处理方案**:
1. **立即处理**:
   - 重启应用实例
   - 扩容服务器资源
   - 清理资源占用
   - 临时增加资源限制

2. **资源优化**:
   - 优化内存使用
   - 调整线程池配置
   - 优化连接池配置
   - 及时释放资源

3. **架构优化**:
   - 水平扩容
   - 资源隔离
   - 限流保护
   - 弹性伸缩

### 原因6: 配置错误
**特征**:
- 最近有配置变更
- 配置项缺失或错误
- 环境变量未设置
- 配置文件语法错误

**处理方案**:
1. **立即恢复**:
   - 回滚到上一个正确的配置
   - 检查配置文件语法
   - 验证环境变量
   - 重启应用加载新配置

2. **配置修正**:
   - 修复错误的配置
   - 使用配置中心管理
   - 配置变更审批流程
   - 配置版本管理

3. **预防措施**:
   - 配置验证
   - 配置测试
   - 灰度发布配置
   - 配置回滚机制

## 紧急处理措施

### 立即操作（5分钟内）
1. **评估影响**: 确定错误率和影响范围
2. **快速止损**: 回滚版本或关闭有问题的功能
3. **重启服务**: 重启应用实例
4. **通知团队**: 通知开发团队

### 短期措施（30分钟内）
1. **定位问题**: 分析日志找出根本原因
2. **修复问题**: 修复代码或配置问题
3. **验证测试**: 测试修复后的功能
4. **重新发布**: 发布修复后的版本

### 长期优化
1. **代码质量**: 提高代码质量，减少bug
2. **测试覆盖**: 增加单元测试和集成测试
3. **监控完善**: 建立完善的错误监控
4. **发布流程**: 优化发布流程，实现灰度发布

## 错误排查命令

### 查看应用日志
```bash
# 查看最近错误
tail -f app.log | grep ERROR

# 统计错误数量
grep -c "level:ERROR" app.log

# 查看特定错误
grep "NullPointerException" app.log

# 分析错误趋势
grep "level:ERROR" app.log | awk '{print $1}' | sort | uniq -c
```

### Java应用诊断
```bash
# 查看线程转储
jstack <pid> > thread_dump.txt

# 查看堆内存
jmap -heap <pid>

# 生成堆转储
jmap -dump:format=b,file=heap.hprof <pid>

# 查看GC日志
jstat -gc <pid> 1000
```

### Python应用诊断
```bash
# 查看traceback
python -c "import traceback; traceback.print_exc()"

# 内存分析
python -m memory_profiler script.py

# 性能分析
python -m cProfile -s time script.py
```

## 验证步骤
1. 确认错误率降到正常水平（<0.1%）
2. 检查应用响应时间恢复正常
3. 验证核心功能正常
4. 确认无新的错误日志
5. 持续监控30分钟确保稳定

## 错误监控指标

### 关键指标
- 错误率（4xx/5xx比例）
- 平均响应时间
- P99响应时间
- 异常数量
- 错误类型分布

### 业务指标
- 请求成功率
- 关键接口可用性
- 用户影响范围
- 业务流程完成率

## 预防措施
1. **代码审查**: 加强代码审查流程
2. **自动化测试**: 完善单元测试和集成测试
3. **监控告警**: 建立错误率监控和告警
4. **灰度发布**: 实施灰度发布策略
5. **回滚机制**: 建立快速回滚机制

- `SlowResponse`: 响应时间过长
- `HighCPUUsage`: CPU使用率过高
