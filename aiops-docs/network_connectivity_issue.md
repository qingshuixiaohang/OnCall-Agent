# 网络连接问题告警处理方案

## 告警名称
- **告警名**: `NetworkConnectivityIssue`
- **告警级别**: 严重
- **触发条件**: 网络延迟超过阈值或连接失败率超过5%

## 问题描述
网络连接问题会导致：
- 服务间调用失败
- 用户访问超时
- 数据同步延迟
- 分布式系统不一致
- 级联故障风险

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确定故障发生时间范围

### 步骤2: 查询网络监控日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `network-metrics`
- **时间范围**: 最近30分钟
- **查询条件**: `latency:>1000 OR packet_loss:>5 OR connection_failed:true`

**查询示例**:
```
地域: ap-guangzhou
日志主题: network-metrics
时间范围: [当前时间-30分钟] 到 [当前时间]
查询语句: latency > 1000 OR packet_loss_rate > 0.05
```

### 步骤3: 查询服务调用日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **查询条件**: `timeout OR connection_refused OR network_error`

### 步骤4: 检查DNS解析
**工具**: `query_logs`
**参数要求**:
- **日志主题**: `system-events`
- **查询条件**: `dns_resolution_failed OR dns_timeout`

### 步骤5: 分析网络拓扑
从日志中分析：
- 哪些服务之间出现网络问题
- 是内部网络还是外部网络
- 是否是特定地域或可用区的问题
- 网络延迟的变化趋势

## 常见原因分析

### 原因1: DNS解析故障
**特征**:
- 无法通过域名访问服务
- DNS查询超时
- 日志中有"Name resolution failure"
- 部分服务可以访问，部分不能

**处理方案**:
1. **立即恢复**:
   - 使用IP地址临时访问
   - 刷新本地DNS缓存
   - 更换DNS服务器（如8.8.8.8）

2. **排查DNS问题**:
   - 检查DNS服务器状态
   - 验证DNS配置是否正确
   - 检查DNS记录是否过期

3. **长期优化**:
   - 配置多个DNS服务器
   - 使用DNS缓存
   - 实现服务发现机制
   - 定期检查DNS健康状态

### 原因2: 网络拥堵或带宽不足
**特征**:
- 网络延迟显著增加
- 丢包率升高
- 带宽使用率接近100%
- 特定时间段出现问题

**处理方案**:
1. **立即缓解**:
   - 启用流量控制
   - 限制非关键业务带宽
   - 启用CDN分流
   - 切换到备用网络链路

2. **流量优化**:
   - 压缩传输数据
   - 启用HTTP/2或QUIC
   - 使用就近接入
   - 优化大文件传输

3. **扩容带宽**:
   - 临时增加带宽
   - 申请弹性带宽
   - 长期规划带宽容量

### 原因3: 防火墙或安全组配置错误
**特征**:
- 特定端口无法访问
- 内外网访问不一致
- 日志中有"Connection refused"或"Timeout"
- 最近有网络配置变更

**处理方案**:
1. **快速恢复**:
   - 检查防火墙规则
   - 验证安全组配置
   - 临时开放必要端口
   - 检查网络ACL

2. **配置修正**:
   - 恢复正确的防火墙规则
   - 检查IP白名单
   - 验证端口配置
   - 测试网络连通性

3. **配置管理**:
   - 使用基础设施即代码
   - 配置变更需要审批
   - 定期审计防火墙规则
   - 建立配置回滚机制

### 原因4: 负载均衡器故障
**特征**:
- 特定实例无法访问
- 流量分配不均
- 负载均衡器健康检查失败
- 部分用户无法访问

**处理方案**:
1. **立即切换**:
   - 将故障实例从负载均衡池中移除
   - 切换到备用负载均衡器
   - 调整健康检查参数

2. **恢复负载均衡**:
   - 重启负载均衡服务
   - 检查配置是否正确
   - 验证后端实例健康状态
   - 重新配置转发规则

3. **优化配置**:
   - 调整健康检查间隔
   - 配置合理的超时时间
   - 实现会话保持（如需要）
   - 监控负载均衡指标

### 原因5: 跨地域或跨云网络问题
**特征**:
- 跨地域调用延迟高
- 专线连接不稳定
- VPN隧道中断
- 云服务商网络故障

**处理方案**:
1. **快速切换**:
   - 切换到同地域服务
   - 使用本地缓存
   - 启用降级策略
   - 临时关闭非关键跨地域调用

2. **网络优化**:
   - 使用云企业网或专线
   - 优化路由配置
   - 启用智能DNS
   - 使用多活架构

3. **容灾方案**:
   - 部署多地域服务
   - 实现异地多活
   - 建立故障转移机制
   - 定期进行容灾演练

## 紧急处理措施

### 立即操作（5分钟内）
1. **确认故障范围**: 确定是单个服务还是全局网络问题
2. **启用降级**: 关闭非关键的网络依赖
3. **切换流量**: 如果有备用网络，立即切换
4. **通知团队**: 通知网络团队和相关开发人员

### 短期措施（30分钟内）
1. **定位根因**: 分析日志和监控数据找出问题根源
2. **修复配置**: 如果是配置问题，立即修正
3. **恢复服务**: 逐步恢复受影响的服务
4. **监控验证**: 持续监控网络指标确保稳定

### 长期优化
1. **网络架构优化**: 优化网络拓扑，减少单点故障
2. **多活部署**: 实现多地域、多可用区部署
3. **监控完善**: 建立全面的网络监控体系
4. **容灾演练**: 定期进行网络故障演练

## 网络诊断命令

### 基础连通性测试
```bash
# ping测试
ping -c 10 example.com

# traceroute路由跟踪
traceroute example.com

# 端口连通性测试
telnet example.com 443
nc -zv example.com 443
```

### DNS诊断
```bash
# DNS解析测试
nslookup example.com
dig example.com
host example.com

# 查看DNS缓存
systemd-resolve --statistics
```

### 网络性能测试
```bash
# 带宽测试
iperf3 -c server_ip

# 网络延迟测试
mtr example.com

# 路由跟踪
traceroute -T -p 443 example.com
```

### 网络统计
```bash
# 查看网络连接
netstat -an | grep ESTABLISHED | wc -l

# 查看网络接口统计
ip -s link show

# 查看路由表
ip route show
```

## 验证步骤
1. 确认网络延迟恢复正常（<100ms）
2. 检查丢包率为0
3. 验证所有服务调用成功
4. 确认DNS解析正常
5. 持续监控10分钟确保稳定

## 预防措施
1. **网络监控**: 建立完善的网络监控体系
2. **多链路备份**: 配置多条网络链路
3. **流量控制**: 实施流量控制和限流
4. **容灾架构**: 设计高可用的网络架构
5. **定期演练**: 进行网络故障演练

## 相关告警
- `ServiceUnavailable`: 服务不可用
- `SlowResponse`: 响应时间过长
- `HighCPUUsage`: CPU使用率过高（可能因网络重试导致）
