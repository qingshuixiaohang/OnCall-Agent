# 数据库问题告警处理方案

## 告警名称
- **告警名**: `DatabaseIssue`
- **告警级别**: 严重
- **触发条件**: 数据库连接失败、慢查询过多或数据库不可用

## 问题描述
数据库问题会导致：
- 应用无法访问数据
- 响应时间急剧增加
- 事务失败
- 数据不一致
- 级联服务故障

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确定故障发生时间

### 步骤2: 查询数据库错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `database-logs`
- **时间范围**: 最近30分钟
- **查询条件**: `level:ERROR OR level:FATAL`

**查询示例**:
```
地域: ap-guangzhou
日志主题: database-logs
时间范围: [当前时间-30分钟] 到 [当前时间]
查询语句: (level:ERROR OR connection_failed) AND db_type:mysql
```

### 步骤3: 查询慢查询日志
**工具**: `query_logs`
**参数要求**:
- **日志主题**: `database-slow-query`
- **查询条件**: `query_time:>1000`

### 步骤4: 查询数据库连接池状态
**工具**: `query_logs`
**参数要求**:
- **日志主题**: `application-logs`
- **查询条件**: `connection_pool OR db_connection`

### 步骤5: 检查数据库资源使用
从日志中分析：
- CPU使用率
- 内存使用率
- 磁盘IO
- 连接数
- 锁等待情况

## 常见原因分析

### 原因1: 数据库连接池耗尽
**特征**:
- 应用日志中有"Connection pool exhausted"
- 新请求无法获取数据库连接
- 连接数达到最大限制
- 等待连接超时

**处理方案**:
1. **立即恢复**:
   - 重启应用释放僵死连接
   - 临时增加连接池大小
   - 启用连接池监控
   - 清理长时间空闲的连接

2. **排查问题**:
   - 检查是否有连接泄漏
   - 查看是否有长事务占用连接
   - 分析连接使用模式
   - 检查数据库最大连接数限制

3. **优化配置**:
   - 合理设置连接池大小
   - 配置连接超时时间
   - 启用连接验证
   - 实现连接池监控告警

### 原因2: 慢查询导致数据库负载过高
**特征**:
- 慢查询日志中有大量记录
- 数据库CPU使用率高
- 响应时间变长
- 大量锁等待

**处理方案**:
1. **立即优化**:
   - 终止执行时间过长的查询
   - 临时添加缺失的索引
   -  kill 阻塞的查询
   - 启用查询缓存

2. **查询优化**:
   - 分析执行计划（EXPLAIN）
   - 优化SQL语句
   - 添加合适的索引
   - 避免全表扫描

3. **架构优化**:
   - 读写分离
   - 分库分表
   - 使用缓存层
   - 查询优化

### 原因3: 数据库锁等待或死锁
**特征**:
- 事务长时间处于等待状态
- 日志中有锁等待或死锁错误
- 应用响应超时
- 数据库CPU使用率高

**处理方案**:
1. **立即处理**:
   - 终止死锁事务
   -  kill 长时间运行的事务
   - 回滚阻塞的事务
   - 检查锁等待链

2. **排查锁问题**:
   - 分析锁等待日志
   - 找出长事务
   - 检查事务隔离级别
   - 查看锁升级情况

3. **优化事务**:
   - 缩短事务执行时间
   - 避免大事务
   - 优化事务顺序
   - 使用合理的隔离级别

### 原因4: 数据库服务器资源不足
**特征**:
- CPU使用率持续高于80%
- 内存不足，使用swap
- 磁盘IO等待高
- 数据库响应变慢

**处理方案**:
1. **立即扩容**:
   - 升级数据库服务器配置
   - 增加CPU和内存
   - 使用更快的磁盘（SSD）
   - 启用只读实例分担读压力

2. **资源优化**:
   - 优化数据库参数配置
   - 调整缓冲池大小
   - 优化日志配置
   - 清理不必要的索引

3. **架构优化**:
   - 读写分离
   - 分库分表
   - 使用缓存减少数据库访问
   - 数据库集群化

### 原因5: 数据库故障转移或重启
**特征**:
- 数据库服务短暂不可用
- 连接断开
- 日志中有数据库重启记录
- 主从切换

**处理方案**:
1. **快速恢复**:
   - 确认主从状态
   - 检查数据一致性
   - 重启应用重建连接池
   - 验证数据库服务正常

2. **故障分析**:
   - 查看数据库错误日志
   - 检查是否有硬件故障
   - 分析资源使用情况
   - 查看操作系统日志

3. **高可用优化**:
   - 配置数据库集群
   - 实现自动故障转移
   - 定期备份数据
   - 建立监控告警

### 原因6: 磁盘空间不足
**特征**:
- 数据库无法写入
- 日志中有"No space left on device"
- 数据库报错
- 事务提交失败

**处理方案**:
1. **立即清理**:
   - 清理临时文件
   - 清理旧日志文件
   - 删除不必要的备份
   - 清理临时表

2. **扩容磁盘**:
   - 扩展磁盘空间
   - 使用更大容量的磁盘
   - 迁移到新磁盘

3. **长期优化**:
   - 实施数据归档策略
   - 定期清理历史数据
   - 使用分区表
   - 监控磁盘使用情况

## 紧急处理措施

### 立即操作（5分钟内）
1. **确认影响**: 评估故障影响范围
2. **启用降级**: 关闭非核心数据库功能
3. **重启连接池**: 清理僵死连接
4. **通知DBA**: 通知数据库管理员

### 短期措施（30分钟内）
1. **解决问题**: 根据原因采取相应措施
2. **监控验证**: 持续监控数据库指标
3. **恢复服务**: 逐步恢复正常服务
4. **数据验证**: 确认数据一致性

### 长期优化
1. **性能优化**: 优化SQL和索引
2. **架构优化**: 实施读写分离、分库分表
3. **监控完善**: 建立全面的数据库监控
4. **容量规划**: 定期评估和规划容量

## 数据库优化命令

### MySQL性能分析
```sql
-- 查看慢查询日志
SHOW VARIABLES LIKE 'slow_query_log';
SHOW VARIABLES LIKE 'long_query_time';

-- 查看当前连接
SHOW PROCESSLIST;

-- 查看锁等待
SHOW ENGINE INNODB STATUS;

-- 查看执行计划
EXPLAIN SELECT * FROM table WHERE condition;

-- 查看索引使用情况
SHOW INDEX FROM table;
```

### PostgreSQL性能分析
```sql
-- 查看慢查询
SELECT * FROM pg_stat_activity WHERE state = 'active';

-- 查看锁
SELECT * FROM pg_locks WHERE NOT granted;

-- 查看数据库大小
SELECT pg_size_pretty(pg_database_size('database_name'));

-- 查看表大小
SELECT pg_size_pretty(pg_total_relation_size('table_name'));
```

### Redis诊断
```bash
# 查看Redis信息
redis-cli INFO

# 查看慢查询
redis-cli SLOWLOG GET 10

# 查看内存使用
redis-cli INFO memory

# 查看键数量
redis-cli DBSIZE
```

## 验证步骤
1. 确认数据库连接正常
2. 检查慢查询数量恢复正常
3. 验证应用响应时间恢复正常
4. 确认无新的数据库错误
5. 持续监控30分钟确保稳定

## 数据库监控指标

### 关键性能指标
- QPS（每秒查询数）
- 连接数使用率
- 缓存命中率
- 锁等待时间
- 慢查询数量

### 资源指标
- CPU使用率
- 内存使用率
- 磁盘使用率
- 磁盘IO
- 网络IO

### 业务指标
- 事务成功率
- 查询响应时间
- 错误率
- 并发连接数

## 预防措施
1. **监控告警**: 建立数据库性能监控和告警
2. **定期优化**: 定期优化SQL和索引
3. **容量规划**: 提前规划数据库容量
4. **备份策略**: 实施定期备份和恢复演练
5. **高可用**: 配置数据库集群和自动故障转移

## 相关告警
- `HighCPUUsage`: CPU使用率过高
- `HighMemoryUsage`: 内存使用率过高
- `SlowResponse`: 响应时间过长
- `ServiceUnavailable`: 服务不可用
